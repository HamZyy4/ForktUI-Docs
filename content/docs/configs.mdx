## Availability

The config manager is optional. `Window.ConfigManager` is initialized only when a window has a `Folder` and the runtime provides the required filesystem functions. It is intentionally unavailable in standard Roblox Studio. Check its type before calling config methods.

```luau
local Window = ForktUI:CreateWindow({
    Title = "My Interface",
    Folder = "MyInterface",
})

local ConfigManager = Window.ConfigManager
if type(ConfigManager) ~= "table" then
    warn("Local config storage is unavailable")
    return
end
```

## Flag elements

Give every persistable element a unique `Flag`. ForktUI currently provides parsers for `Colorpicker`, `Dropdown`, `Input`, `Keybind`, `Slider`, and `Toggle`.

```luau
local MainTab = Window:Tab({ Title = "Settings" })

MainTab:Toggle({
    Title = "Enable option",
    Flag = "EnableOption",
    Value = false,
})

MainTab:Slider({
    Title = "Volume",
    Flag = "Volume",
    Value = { Min = 0, Max = 100, Default = 50 },
})
```

## Create, save, and load

```luau
local Config = ConfigManager:Config("default")

local saved, saveResult = Config:Save()
if not saved then
    warn("Save failed:", saveResult)
end

local loaded, loadResult = Config:Load()
if not loaded then
    warn("Load failed:", loadResult)
end
```

`Save()` and `Load()` return a success boolean followed by the saved data or an error message. Create the flagged elements before loading so the stored values can be applied to their controls.

## Other methods

```luau
Config:Set("layout", "compact")
print(Config:Get("layout"))
Config:SetAutoLoad(true)
print(Config:GetData())

local names = ConfigManager:AllConfigs()
local automatic = ConfigManager:GetAutoLoadConfigs()
local existing = ConfigManager:GetConfig("default")

Config:Delete()
ConfigManager:DeleteConfig("default")
```

`ConfigManager:SetPath("custom/folder")` changes the local config directory when the runtime has folder APIs. Config names are normalized to safe filename characters. Use unique names and flags.

> Local config files are client-side preferences, not secure storage. Do not store passwords, access tokens, private keys, or authorization decisions in them. Use server-side persistence and validation for game data that must be trusted.
